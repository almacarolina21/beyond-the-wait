# Data Directory

This project uses **three kinds of data**. Every dataset and every metric
the app displays is labeled with one of these provenance tags.

| Tag | Folder | What it is | Committed to Git? |
|-----|--------|-----------|-------------------|
| `PUBLIC` | `public/raw`, `public/processed` | Official, publicly released **aggregate** hospital metrics (e.g., CMS Care Compare, NYS Department of Health / SPARCS summary tables). Used for **context and calibration only**. | Raw: no (re-downloaded by script). Processed: small reference tables yes, with a source note. |
| `SYNTHETIC` | `synthetic/` | Fake patient-level records generated by our code from documented assumptions. No real person exists in this data. | No (regenerated from a seed). |
| `SIMULATED` | (in memory / `evals/results`) | Outputs from the SimPy model run on synthetic patients. | No. |

## Rules

1. **No real patient-level data, ever.** No PHI, no de-identified record-level
   extracts, no employer data, no screenshots of real dashboards.
2. Every public source must be recorded in `public/SOURCES.md` (added in
   Milestone 2) with URL, publisher, measure definition, reporting period, and
   retrieval date.
3. Public metrics describe *what* happened at a hospital level. They do **not**
   tell us *why*. The app must never present a cause for a real hospital's
   delays that isn't documented in the source.
4. `.gitignore` keeps regenerable files out of Git for tidiness. It is **not**
   a privacy safeguard — it can't inspect file contents. Rule 1 is what
   protects privacy.
