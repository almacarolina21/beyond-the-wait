# Dashboard — Beyond the Wait (Milestones 7, 7.1, and 8)

An interactive Streamlit + Plotly app that presents the project to healthcare
leaders and technical reviewers. **No API key and no internet connection
needed** once the data files below exist: the AI explanation panel (Milestone 8)
runs in DEMO (mock) mode unless live Claude access is explicitly enabled (§9).

```bash
source .venv/bin/activate
python -m beyond_the_wait.analysis.whatif_demo --seeds 30 --sensitivity-seeds 20 --workers 8   # once, ~6 min
streamlit run app/streamlit_app.py
# then open http://localhost:8501
```

---

## 1. Pages and audiences

| Page | For | Data | Provenance |
|---|---|---|---|
| **Overview** | Everyone | Three featured findings generated from the verified bundle; links into the app | Defines PUBLIC / SYNTHETIC / SIMULATED |
| **Bronx Public Data** | Leaders, reviewers | Committed Milestone 2 tables | **PUBLIC** only |
| **Fictional Patient Flow** | Leaders | One live single-seed run (≈1 s, cached), plus generated patients | **SYNTHETIC** inputs, **SIMULATED** outcomes |
| **What-If Lab** | Leaders | Precomputed 30-seed paired comparisons; optional verified AI explanation | **SIMULATED** |
| **Sensitivity, Validation & Methods** | Reviewers | Sensitivity grid, gate checks, CI vs. PI, limitations | **SIMULATED** |
| **AI Explanation Evaluation** | Reviewers | Offline evaluation of the explanation guardrails (hand-written cases) | **SIMULATED** packets; no API calls |

## 2. Architecture and data flow

```
app/streamlit_app.py              navigation (st.navigation), theme, sidebar note
app/views/*.py                    thin page scripts: layout + text, no calculations
src/beyond_the_wait/dashboard/
    data.py    loaders and table shaping -> existing APIs only
    charts.py  Plotly figure builders (provenance in every title)
    theme.py   palette, Plotly template, badges, CSS
    ui.py      Streamlit helpers, caching, callouts
    ai_panel.py  What-If explanation panel (Milestone 8; calls interpretation/)
```

| Data | Source API | Verified by |
|---|---|---|
| PUBLIC | `load_processed_measures()` (Milestone 2) | `require_provenance(PUBLIC)` |
| One SIMULATED run | `run_simulation` → `validate_run` → `release_for_interpretation` | The Milestone 5 gate. BLOCKED shows no numbers. |
| Generated patients | `generate_patients` | `require_provenance(SYNTHETIC)` |
| Multi-seed results | `analysis/results_bundle.load_bundle()` | SHA-256 fingerprints, SIMULATED labels, valid statuses; BLOCKED comparisons removed and listed |

**No calculation logic lives in the UI.** The dashboard needed per-patient
boarding times, so `detailed_metrics.boarding_values()` was extracted and is
now shared by the existing summary and the box plot.

### The results bundle

`whatif_demo` writes `data/synthetic/experiments/` (git-ignored, reproducible):
`comparisons.csv`, `comparison_checks.csv`, `archetypes.csv`,
`sensitivity.csv`, `stability.csv`, and `manifest.json` (settings, seeds,
per-comparison status, carried CAUTIONs, lever effects, and a SHA-256 for
every file). The dashboard **refuses** the bundle if any file is missing,
altered, mislabeled, or has a BLOCKED comparison that still contains numbers.

### Caching

| What | Cached by | Why |
|---|---|---|
| Public data, results bundle | path + file modification time | Rebuilding a file reloads it automatically |
| Live run | (seed, days), max 8 entries | About 1 s per run; days capped at 14 |
| 30-seed experiments | **never run by the app** | Precomputed only |

## 3. Safeguards against misinterpretation

- Every chart title starts with **PUBLIC**, **SYNTHETIC**, or **SIMULATED**.
  Public and simulated data are on separate pages and never share a chart.
- Unavailable and suppressed public values appear as **text** ("Not available
  [footnote 1]", "Suppressed (S)"), never as zero bars.
- The page states reporting periods (OP-18: CY 2025; OP-22 and EDV: CY 2024)
  and warns against comparing them or ranking hospitals.
- Effects are a dot plus the **95% CI of the mean difference**, with the zero
  line marked, labeled **"Lower / Higher within the fictional model"** (neutral
  blue / orange), never better, worse, safe, or recommended.
- Plain-language text (Overview findings, What-If "What this shows") is
  generated by `data.key_findings()` / `data.interpretation()` from verified
  bundle rows only. No figure is typed into the page; BLOCKED comparisons are
  absent from the bundle and therefore can never be featured.
- Utilization changes carry the note that lower utilization describes
  workload, not quality.
- The file-verification PASS line states explicitly that it is **not**
  clinical or real-world validation.
- When an intervention shortens one stage but lengthens another, a callout
  says that congestion moved.
- The **ESI-1 limitation** appears on the Patient Flow and Methods pages; the
  "not a recommendation" note appears on the Overview and the What-If Lab. The
  full model-evidence note appears once (What-If "How to read" expander), not
  repeated.
- BLOCKED comparisons are listed in an error and can't be selected or plotted.
  CAUTION reasons are shown per comparison as readable sentences
  (`analysis/check_descriptions.py`), with the raw check code beside them.
- Sensitivity cells in an overload regime are marked **stress** and excluded
  from stability verdicts.

## 4. Visual design

- Restrained light theme (`.streamlit/config.toml`), system font stack (works
  offline), 1,180 px content width, spacious line height, cards for concepts.
- Colors come from the documented reference palette of the project's
  data-visualization method, used unmodified:
  - categorical slots in fixed order for stages and series;
  - a one-hue blue ordinal ramp for ESI (darker = more urgent);
  - status colors reserved for PASS / CAUTION / BLOCKED, always with an icon and a word.
- **The palette validator was not run**: Node.js isn't installed on the
  development machine. To compensate, every mark also has a text label, hover
  text, or legend entry, so no meaning depends on color alone.
- One y-axis per chart; legends for 2+ series; units in axis titles.
- Narrow screens: Streamlit columns stack, and the CSS reduces side padding below 700 px.

## 5. Security and reliability

- No Claude calls unless live mode is enabled **and** a visitor clicks *Explain
  these results*; no file uploads (`maxUploadSize = 1`), no free-text prompt box,
  no YAML upload or arbitrary file execution. Data paths are fixed (or set by the
  `BTW_RESULTS_DIR` / `BTW_PUBLIC_DIR` environment variables, used in tests).
- `server.address = "localhost"`: the app isn't reachable from the local network.
- `browser.gatherUsageStats = false`: no Streamlit telemetry.
- Missing or invalid files produce a clear message and the command to fix it, not a crash.

## 6. Testing

- **Data layer:** provenance verification, unavailable/suppressed values,
  periods, units, live run, BLOCKED live run, run cap, bundle helpers.
- **Results bundle:** fingerprint tampering, wrong provenance, missing files
  and columns, bad version and status, BLOCKED comparisons excluded (and
  rejected if they carry numbers), BLOCKED sensitivity cells lose their numbers.
- **Charts:** provenance titles, no real hospital names in simulated charts,
  values matching the source, error bars equal to the CI, percentage-point
  scaling, prediction interval wider than the CI, empty inputs.
- **Pages (Streamlit `AppTest`, headless):** every page runs without
  exceptions; the missing bundle shows build instructions; a tampered bundle
  is refused; a BLOCKED comparison is listed but not selectable or plotted;
  selectors update the content; safety messages are present.
- **Live server check:** the health endpoint returns `ok` at `http://localhost:8501`
  and the network address is refused.

## 7. Milestone 7.1: layout, readability, and UX

### Chart layout rules (enforced by `charts.layout_problems()` and tests)

| Rule | How |
|---|---|
| Category labels never clip | `automargin` on both axes (template); axis labels ≤ 40 characters via `data.SHORT_LABELS` / clipping, full names in hover |
| Title, subtitle, legend never overlap | Title + Plotly `subtitle` in a fixed 92 px top band (container coordinates); legends in a reserved bottom band (container coordinates) |
| Height fits content | 46 px per category row + title band + axis band (+ legend band) |
| Every trace has hover text | checked |
| Provenance first in every title | checked |

Fixes found by rendering the charts (not visible from the code alone):
- **NYS duplicate names:** two NYS sites (IDs 001164 and 001178) are both
  published as "BronxCare Hospital Center". The bar chart overlaid them and hid
  the 1,636 value; duplicate names now get their own row with the facility ID.
- **Stage colors:** 8 stages but 7 categorical slots, so boarding reused the
  first color. Each stage now has a fixed color (boarding = dark gray), and
  legends are in chronological order.
- **Hollow marker:** "Identical in both arms" now differs from "No detectable
  change" by shape, not only by the shared gray.
- **Overlapping bar labels** on the shift chart moved to hover.
- **Side-by-side hourly charts** clipped titles at laptop width; now stacked.
- **Wide tables:** summary tables use `st.table` (wraps to page width); long
  stability verdicts and tab names shortened.

### Page structure
- **Overview:** headline, one-sentence purpose, the principle line, three
  generated findings (SIMULATED, CAUTION chips), links into the What-If Lab /
  Patient Flow / Public Data; the data-type cards and can/cannot list follow;
  long explanations in expanders.
- **What-If Lab:** title → one-line disclaimer → outcome selector + chart →
  "What this shows" → intervention detail (status, why CAUTION, table, stage
  chart, congestion callout) → archetypes → methods and validation expanders.

## 8. Visual inspection

**Performed (Milestone 7.1):** full-page screenshots of all five pages were
captured from the running app (`http://localhost:8501`) with headless Chrome
driven over the DevTools protocol, and reviewed: all five pages at 1024 px,
Public Data / Patient Flow / Methods / What-If at 1280 px, and Overview /
What-If at 1440 px. A DOM probe reported, for every page at 1024 px: no horizontal page
scroll, no visible element wider than the viewport, and no Plotly tick label,
title, or legend text outside its chart. Each chart was also rendered alone at
760 px and reviewed.

**Not covered:** phone widths, dark mode, browser zoom, screen readers, and
interactive states (hover tooltips, open expanders, other selector values).
Remaining checks for a human reviewer:
1. Hover tooltips on the What-If and archetype charts.
2. Open each expander on the What-If Lab and Methods pages.
3. A window narrower than 1,000 px, and browser zoom at 125%.
4. The sensitivity heatmap for each intervention.

## 9. Milestone 8: AI explanation panel

Full design: [AI_INTERPRETATION.md](AI_INTERPRETATION.md).

**Position.** The panel is in the What-If Lab, after "One intervention in detail" and before
"Archetypes". It explains the selected **intervention × outcome**. Charts and
tables stay above it, unchanged.

**What the visitor sees:**
- **Mode label:** `DEMO · mock, not Claude` or `LIVE · Claude API`, with a one-line note.
- **Evidence description:** the packet ID and the number of facts. It states that no
  patient-level records are included and nothing is sent before a click.
- **The button** *Explain these results*. Clicking it is the **only** way to make a
  request. Widget changes and page loads never call a provider (tested with a
  counting fake client).
- **A verified result**, inside a bordered box:
  - the mode, a PASS chip ("Passed 11 local checks"), the model name, and the packet ID;
  - the banner *"Decision support for human review. Based on simulated data."*;
  - **Key result (calculated by Python)**: one sentence built from the packet only
    (Milestone 9), so the main result never depends on generated wording;
  - the summary;
  - key findings, tradeoffs, uncertainties, and limitations, each with its evidence IDs;
  - questions for qualified people, and the disclaimer;
  - token usage (LIVE only).

  Two expanders follow: the evidence used (values formatted by Python) and the checks
  run, with what those checks cannot establish.
- **A result that needs human review** (Milestone 9): every check passed, but the
  faithfulness layer found wording it cannot vouch for (a mechanism, a size judgment,
  an omitted opposite movement, unvetted words). It is shown with a
  "⚑ NEEDS HUMAN REVIEW" chip, a warning listing each flag in plain words, and
  "⚑ needs review" next to each flagged sentence.
- **A rejected result:** a warning and the names of the failed checks. **None** of the
  generated text is shown.
- **An error** (missing key, rate limit, timeout, refusal, …): a readable fallback
  message, and the rest of the page is unaffected.

**Caching.** Each explanation is stored in session memory under its packet ID, mode
and model. Returning to a selection shows its saved explanation without a new
request, and an explanation is never shown for a different selection. Nothing is
written to disk.

**Wording fixes made at the same time:**
- The What-If header no longer says pairing makes differences "come from the change,
  not luck". It now says pairing removes *much* of the chance variation, and the 95%
  intervals show what remains.
- "Why CAUTION" now lists readable sentences instead of check codes.

## 10. Milestone 9: AI Explanation Evaluation page

`app/views/ai_evaluation.py`, in its own sidebar group ("AI explanation ·
offline evaluation"). It runs the offline evaluation suite on load (cached) and
never calls the API.

1. **Blind results**: one row per locked held-out round, from its lock file:
   unsafe detected, unsafe accepted, useful text rejected or sent to review, and
   whether the case file is unchanged since locking.
2. **Current run**: choose a split; four metrics, the confusion matrix
   (should vs. did), results by risk category, and every case the checks got
   wrong or only partly right, with its first signal. Held-out splits are
   labeled "after fixes, not blind".
3. **What this does not show**: real Claude output is untested, same-author
   cases, word patterns are not understanding, coverage is not safety.

Full method and numbers: [AI_EVALUATION.md](AI_EVALUATION.md).
